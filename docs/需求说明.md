# 数据项趋势组件需求说明

## 1. 文档目的

本文定义「数据项趋势」独立组件的功能范围、入参、交互、接口、主题和宿主接入方式。供产品、开发和测试评审。未写入本文的能力视为本版本不做。

本文记录的是已确认需求，不是实现计划。自定义数据项树仅列为后续能力，不进入本版本。

## 2. 功能目标

组件用于在当前页面查看非信号数据项的历史趋势，并按启用阈值画阈值线。它是诊断分析「综合趋势」的简化形态，不包含设备树、工况分割、分析模板、信号波形和特征统计。

组件以独立 npm 包发布。宿主决定用抽屉还是弹窗承载；包提供内容区，并可选提供抽屉、弹窗外壳。

当前调试宿主是本仓库 `playground`。dosiv-v2 暂不引入本组件，设备详情看板实时值和「分析」仍跳转诊断分析页。

## 3. 功能边界

### 3.1 本版本包含

- 立刻加载并绘制最多 10 条数据项趋势（可跨设备）。
- 待选区域：按设备或数据项清单挑选要画的数据项；待选参数为空时不展示该区域。
- 时间查询：开始/截止时间、快捷档、时间窗平移。
- 跳转诊断分析：当前勾选须为同一设备；单条带三元组打开；多条最多 5 个，写入 `sessionStorage.deviceKpi` 后只带 `deviceCode` 打开。
- 一张图、多条曲线、共用 Y 轴。
- 启用阈值的阈值线（虚线，按等级着色），开关默认关闭。
- 主题：`dark`、`light`、`remote-blue`，与 dosiv-v2 设备详情抽屉一致。
- playground：Mock 数据或经 vite 代理接入后端，便于独立调试。

### 3.2 本版本不包含

- 诊断分析综合趋势中的设备树、面包屑、收藏、复制、工况分割、分析模板、展开搜索、聚合方式、小数位、特征统计表、报警事件标点、信号/波形分析。
- 自定义数据项树（后续再做）。
- 使用 `LPBI01/getKpiValueListByCondition`、`getDataListByCondition`、`AAAA01/queryTimeSeriesHistoryData` 作为趋势数据源。
- 使用 `LPBI01/getKpiThresholdListByCondition` 作为阈值数据源。
- 使用 `listDataItemStatusByPageQuery` 或 `getPointAndKpiListForWorkCondition` 作为设备下数据项列表数据源。
- 依赖 ant-design-vue。
- 账号级配置保存、跨页同步选中数据项。
- 将本组件接入 dosiv-v2（暂缓）。

## 4. 术语

| 术语 | 说明 |
| --- | --- |
| 数据项 | 逻辑测点上的一个采集指标。身份由设备编码、测点编号、采集标识组成。 |
| 非信号数据项 | `isSignal === false`（接口字段 `signal !== true`）的数据项。本组件只处理这类数据项。 |
| 采集标识 | 写入 busout 请求体 `kpiId` 的值。优先用 `collectKpiId`，不使用数字内部编号，不优先使用中文展示名。 |
| 趋势入参 | 打开时立刻要绘制的数据项清单和时间窗。 |
| 待选区域 | 供用户勾选数据项的区域。数据源可以是设备或数据项清单。 |
| 宿主 | 引用本 npm 包的应用。当前调试宿主是本仓库 playground；dosiv-v2 为计划中的业务宿主。 |
| 内容区 | 查询栏、趋势图、可选待选区域。不含抽屉或弹窗外壳。 |
| 启用阈值 | 阈值接口中 `enabled === '1'`（页面模型 `status === '启用'`）的规则。停用规则不请求后也不绘制。 |

## 5. 系统如何工作

打开组件后按下面顺序工作。

1. 读取趋势入参。数据项超过 10 条时只保留前 10 条，并提示其余未加载。未传时间则截止时间为当前时刻，开始时间为当前时刻减 2 小时。
2. 若待选参数为空，不渲染待选区域，内容区只保留查询栏和趋势图。
3. 若待选为设备：请求该设备非信号数据项列表，列表默认不勾选；再把趋势入参中的数据项勾上（能匹配到的）。匹配不到时仍绘制趋势入参中的数据项。
4. 若待选为数据项清单：清单即为候选集合，勾选规则同第 3 步。
5. 对当前勾选（或趋势入参中）的每条数据项各请求一次聚合历史，画在同一张图上。
6. 「阈值线」默认关闭，不请求阈值。用户打开开关后，按当前勾选的数据项请求启用阈值并画虚线；关闭开关只隐藏已画的线，已请求结果可缓存。
7. 用户改时间、点快捷档、平移时间窗、点查询、改勾选后，按当前时间窗和当前勾选重查趋势。阈值开关仍为打开时，同步按新勾选刷新阈值线。

## 6. 入参

入参分成两块，可同时传入。

### 6.1 趋势入参（立刻画图）

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 数据项清单 | 是（可为空数组） | 要立刻绘制的数据项，可跨设备。 |
| 开始时间 | 否 | 毫秒时间戳或可转为毫秒的时间。未传则用默认时间窗。 |
| 截止时间 | 否 | 同上。 |

数据项身份至少包含：`deviceCode`、`pointId`（测点编号）、`kpiId`（采集标识）。展示名、测点名称有则用于图例和待选列表。

约束：

- 最多绘制 10 条。超出时加载前 10 条，提示其余未加载。
- 空清单且待选也未勾选时，图为空，不发趋势请求。

### 6.2 待选参数

可为空。为空则不展示待选区域，用户不能再挑其他数据项，只能看趋势入参中的数据项（仍可改时间）。

| 类型 | 说明 | 本版本查询/选择方式 |
| --- | --- | --- |
| 设备 | 传入设备编码（及可选设备名称） | 请求该设备数据项列表，只展示非信号项，供勾选。 |
| 数据项清单 | 候选数据项集合，可跨设备 | 以清单为候选，供勾选。 |
| 自定义数据项树 | 后续能力 | 本版本不实现。 |

与趋势入参同时传入时：待选区域展示候选；趋势入参中的数据项若出现在候选中则勾选，并立刻画图。匹配不到候选时仍绘制趋势入参。典型用法：趋势为当前一条数据项，待选为该设备。

### 6.3 主题

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `theme` | 否 | `'dark'` \| `'light'` \| `'remote-blue'` |

未传时：若宿主 `html[data-theme]` 已是上述三者之一则跟随，否则为 `remote-blue`。

根节点设置 `data-theme`，样式使用与设备详情抽屉相同的 CSS 变量，包括 `--chart-series-*`、`--chart-text`、`--chart-grid`、`--danger`、`--warning`、`--notice`。查询栏控件、提示文案和图表坐标轴均走这套变量。

### 6.4 请求注入

宿主注入请求能力，不在包内写死 token 头。建议注入统一 `request` 方法，由宿主按路径带上 `x-token`、`token` 或 `Xplat-Token`。

包不依赖宿主路由、Pinia 或设备详情内部模块。

playground 提供两种 `request`：Mock（内存数据）和后端代理（vite `PROXY_TARGET`，写法与 dosiv-v2 的 `vite.config.ts` 相同）。

## 7. 界面

### 7.1 外壳

抽屉还是弹窗由宿主决定。包导出：

- `TrendPanel`：内容区，必选。
- `TrendDrawer`、`TrendModal`：可选外壳。宿主也可以只要内容区，自己包外壳。

### 7.2 查询栏

包含：

- 开始时间、截止时间。
- 快捷档：下拉选择。选项为 5 分钟、10 分钟、30 分钟、2 小时、8 小时、24 小时、2 天、7 天、14 天、30 天、60 天、90 天。
- 时间窗平移：`前移` + 档位下拉 + `后移`。档位与快捷档相同。
- 查询按钮。
- 诊断分析按钮。

不包含：聚合方式、小数位、展开搜索、工况、模板。

行为：

- 未传时间：截止 = 现在，开始 = 现在 − 2 小时。
- 选快捷档：窗口长度改为该档，截止时间保持不变（默认仍是现在），然后立刻重查。
- 前移/后移：按当前档位整体滑动；后移后截止时间不超过现在。
- 诊断分析：未勾选则提示先勾选；跨设备则提示须同一设备。单条按 `deviceCode`、`pointId`、`collectKpiId`、当前时间窗打开。多条最多 5 个，写入 `sessionStorage.deviceKpi`（不查接口），URL 只带 `deviceCode`。落地页读取 `deviceKpi` 后勾选对应树节点。
- `aggregateFunc` 固定为 `2`（最大值），`reserveDecimal` 固定为 `3`，界面不暴露。

### 7.3 趋势图

- 一张图、多条曲线、共用 Y 轴。不同单位会画在同一坐标上。
- 图例与曲线名称展示为「设备编码·测点名称·数据项展示名称」；测点名称缺失时用测点编号，展示名称缺失时用采集标识。
- 无数据（接口 `code: 200` 且 `data: null`，或 `timestamps`/`values` 为空）：空图，不当失败。
- 请求失败：该数据项不画线，并提示该条加载失败，不阻断其他曲线。

### 7.4 阈值线

- 开关文案为「阈值线」，默认关闭。
- 打开后才请求阈值，只画启用规则。
- 同一数据项同一等级有多条启用规则时全部画线，不按看板「每等级只留一条」。
- 单阈值：一条水平虚线，位置为阈值数值。
- 介于/上下限：两条水平虚线（X、Y），不画带状区域。
- 颜色：危险 `--danger`，警告 `--warning`，注意 `--notice`。
- 关闭开关：隐藏已画的线，不丢弃缓存。
- 悬停阈值标签：展示三元组和条件。条件编码与设备详情数据看板一致：`01` 等于、`02` 不等于、`03` 大于、`04` 大于等于、`05` 小于、`06` 小于等于、`07` `介于[X,Y]`、`08` `介于(X,Y)`、`09` `上下限[X,Y]`、`10` `上下限(X,Y)`。

### 7.5 待选区域

- 设备类型：展示该设备非信号数据项，默认不勾选（除非趋势入参命中）。
- 设备类型额外按数据项展示名称聚合：展示聚合后的名称和数量。点击后清空当前选中和趋势图数据，改为选中该名称下的全部数据项并重查；超过上限时只取前 10 条并提示。
- 清单类型：展示传入清单，勾选规则同上。不提供按展示名称聚合。
- 勾选变化后按当前时间窗重查趋势；阈值开关打开时同步刷新阈值线。
- 勾选总数仍受 10 条上限约束：达到 10 条后禁止再勾并提示。

## 8. 接口

三条接口均由包内调用，经宿主注入的 `request` 发出。

### 8.1 设备下数据项列表

与设备详情「数据项」标签页相同。

- 方法/路径：`POST /dosis/service/ISDV01/getKpiValueListByBusFilterDoGet`
- 请求体：`{ "params": { "deviceCode": "<设备编码>", "dataItemLabel": null } }`
- 解析：`result.AllDateList` 按测点展开。
- 过滤：只保留 `signal !== true` 的项。
- 后续趋势、阈值使用：`deviceCode` + `pointId` + `kpiId`（采集标识）。

### 8.2 历史趋势

契约见《获取聚合数据》（智维 CLI / Apifox api-451711306）。

- 方法/路径：`POST /iehm-cloud/api/v1/busout/timeSeriesService/getAutoAggregateDataListByCondition`
- 请求头：由宿主注入；文档约定 `Xplat-Token`。
- 请求体示例：

```json
{
  "startTimeMS": 1768972812000,
  "endTimeMS": 1768980012000,
  "aggregateFunc": 2,
  "reserveDecimal": 3,
  "deviceCode": "310224P15",
  "pointId": "00",
  "kpiId": "HF2_ONTOLOGY_WALKBM_DISPLACE_SENSOR2_FBK_VALUE"
}
```

- `kpiId` 使用采集标识，不使用数字内部编号。
- 每条选中数据项单独请求一次。
- 响应：`data.timestamps`（纳秒字符串）与 `data.values[0]` 按索引对齐画线。
- `code: 200` 且 `data: null`：按无数据处理。

### 8.3 阈值

与设备详情页相同。

- 方法/路径：`POST /api/threshold/customized/getThresholdListByCondition`
- 请求体：`{ "tags": ["deviceCode.pointNo.dataItemCollectName", ...] }`
- 只使用 `enabled === '1'` 的规则画线。

不使用诊断分析页的 `LPBI01/getKpiThresholdListByCondition`。

## 9. 包与宿主

### 9.1 技术边界

- Vue 3 + echarts。
- 自带样式，贴近 dosiv-v2 设备详情抽屉，并支持第 6.3 节三套主题。
- 不依赖 ant-design-vue。
- 仓库：https://github.com/gray0128/TrendAnalysisComponent ；npm 包名 `@gray0128/trend-analysis-component`。

### 9.2 当前调试宿主（playground）

`npm run dev` 启动 playground。数据源可选 Mock 或后端代理。后端代理的 `PROXY_TARGET` 写在 `vite.config.ts`，切换环境只改这一处。

### 9.3 dosiv-v2 接入（暂缓）

dosiv-v2 暂不安装本组件。设备详情看板实时值和「分析」仍调用 `openDdsatAnalyze`，新标签打开诊断分析。

后续接入时，替换上述两处跳转，打开时：

- 趋势入参：当前这一条数据项；时间默认最近 2 小时。
- 待选参数：当前设备。
- 主题：当前平台主题。

## 10. 不变量

下列条目可验收。违反即本版本不合格。

- 不得绘制 `isSignal === true` 的数据项。
- 不得同时绘制超过 10 条趋势。
- 不得在「阈值线」关闭时为画线而请求阈值。
- 不得把停用阈值画成阈值线。
- 未传时间时，时间窗必须是最近 2 小时。
- `aggregateFunc` 必须为 `2`，`reserveDecimal` 必须为 `3`。
- 主题取值只能是 `dark`、`light`、`remote-blue`。
- 待选参数为空时，不得渲染待选区域。

## 11. 验收标准

1. 只传趋势清单（≤10 条、可跨设备）、不传待选：无待选区域，图上为这些曲线，可改时间后重查。
2. 趋势清单 >10 条：只画前 10 条，有超出提示。
3. 只传设备、不传趋势清单：展示该设备非信号列表且不勾选，图为空，不发趋势请求。
4. 趋势一条 + 待选为该设备：列表加载、该项勾选、自动画趋势。
5. 未传时间：窗口为最近 2 小时。
6. 快捷档与前移/后移改变时间窗并重查；后移截止不超过现在。
7. 阈值开关默认关；打开后出现启用规则虚线；双阈值画两条线；停用规则不出现。
8. 切换 `dark` / `light` / `remote-blue` 后面板、图、阈值线颜色与设备详情抽屉一致。
9. playground 可用 Mock 或后端代理独立调试。
10. 宿主可以只用 `TrendPanel` 放进自有抽屉或弹窗。
11. 待选为设备时：按数据项展示名称聚合，展示名称和数量；点击后清空当前选中并绘制该名称下的数据项，仍受 10 条上限。
