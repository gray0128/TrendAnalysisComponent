# 数据项趋势组件接入指南

本文说明宿主如何把 `@gray0128/trend-analysis-component` 接到现有 Vue 3 应用。读者是实现接入的开发者。

功能范围、界面行为和接口契约以 [需求说明](需求说明.md) 为准。本文只写接入步骤、入参和必须由宿主提供的能力。

## 1. 包提供什么

包提供内容区 `TrendPanel`，以及可选外壳 `TrendDrawer`、`TrendModal`。

内容区包含：查询栏、趋势图、可选待选区域。趋势图支持多曲线共用 Y 轴、阈值虚线、X 轴完整时间点（年月日 时分秒）、最右侧 Y 轴视窗调节滑块以及鼠标滚轮缩放。

组件不包含 playground 顶部的数据源 / token / 设备编码调试条。外壳（抽屉或弹窗）默认由宿主自己提供。

包不提供：

- 登录、token 存储
- 路由、Pinia、设备详情内部模块
- ant-design-vue 依赖
- 设备树、工况分割、分析模板、信号波形

## 2. 前置条件

- Vue `^3.5.0`（peer dependency）。echarts 由包自行依赖。
- 宿主能把下列路径转发到对应后端，或在注入的 `request` 里改写为绝对地址：
  - `POST /dosis/service/ISDV01/getKpiValueListByBusFilterDoGet`
  - `POST /iehm-cloud/api/v1/busout/timeSeriesService/getAutoAggregateDataListByCondition`
  - `POST /api/threshold/customized/getThresholdListByCondition`
- 未注入 `request` 时，组件抛出 `data-item-trend: request is not installed`。

## 3. 安装

```bash
npm install @gray0128/trend-analysis-component@0.1.6
```

依赖从 npm registry 安装。宿主项目的 `package.json` 和锁文件不得使用本地目录、`file:` 依赖或临时 tarball 路径，否则其他环境无法通过 `npm ci` 还原依赖。

必须引入样式：

```ts
import '@gray0128/trend-analysis-component/style.css'
```

## 4. 注入 request

在应用入口调用 `app.use`，注入统一 `request`。包不在内部写死 token 头；由宿主按路径带上 `x-token`、`token` 或 `Xplat-Token`。

```ts
import { createApp } from 'vue'
import TrendAnalysis from '@gray0128/trend-analysis-component'
import '@gray0128/trend-analysis-component/style.css'
import type { TrendRequest } from '@gray0128/trend-analysis-component'

const request: TrendRequest = async (url, init) => {
  const res = await fetch(url, {
    method: init.method ?? 'POST',
    headers: {
      'Content-Type': 'application/json',
      ...init.headers,
    },
    body: init.data != null ? JSON.stringify(init.data) : undefined,
  })
  return res.json()
}

const app = createApp(App)
app.use(TrendAnalysis, { request })
app.mount('#app')
```

`request` 签名：

```ts
(url: string, init: {
  method?: 'GET' | 'POST'
  data?: unknown
  headers?: Record<string, string>
}) => Promise<unknown>
```

组件只传相对路径和 `data`。鉴权头、`userId`、错误处理由宿主完成。

playground 按路径附加请求头的方式可作为参考（不是包内写死的行为）：

| 路径前缀 | 附加头 |
| --- | --- |
| `/api/threshold` | `token` |
| `/iehm-cloud/api/v1/busout` | `x-token`、`Xplat-Token` |
| 其他 | `x-token` |

有 `userId` 时，playground 还会带 `userId` 头。

## 5. 选择外壳

| 导出 | 用途 |
| --- | --- |
| `TrendPanel` | 内容区。推荐放进宿主自有抽屉或弹窗。 |
| `TrendDrawer` | 可选右侧抽屉弹窗。缺省外壳。点击遮罩、右上角关闭按钮或按 `Escape` 键触发 `close`。 |
| `TrendModal` | 可选普通弹窗。点击遮罩、右上角关闭按钮或按 `Escape` 键触发 `close`。 |

推荐用法：宿主自己管理打开 / 关闭状态，内部只放 `TrendPanel`。使用包内外壳时，缺省选 `TrendDrawer`。

`TrendDrawer` 额外参数：

| Prop | 类型 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `widthPercent` | `number` | `80` | 相对页面宽度的百分比。小于 20 按 20，大于 100 按 100。 |

`TrendModal` 额外参数：

| Prop | 类型 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `size` | `ModalSize \| string` | `'1040*720'` | 固定尺寸档。可选 `'1040*720'`（缺省，宽 1040px 高 720px）、`'1280*800'`（宽 1280px 高 800px）或 `'fullscreen'`（全屏铺满）。对历史档位 `'large'`、`'xlarge'`、`'default'` 自动平滑兼容。小屏自动按视口自适应。 |

两者均透传 `showPicker`、`diagnoseBaseUrl`。包导出类型 `ModalSize`、常量 `MODAL_SIZES` 与缺省值 `DEFAULT_MODAL_SIZE`。

```vue
<script setup lang="ts">
import { TrendPanel } from '@gray0128/trend-analysis-component'
import type { PickerInput, Theme, TrendLoadInput } from '@gray0128/trend-analysis-component'

defineProps<{
  trend: TrendLoadInput
  picker?: PickerInput | null
  theme?: Theme
}>()
</script>

<template>
  <TrendPanel
    :trend="trend"
    :picker="picker"
    :theme="theme"
    diagnose-base-url="/ddsat/"
  />
</template>
```

使用包内抽屉：

```vue
<TrendDrawer
  v-if="open"
  :trend="trend"
  :picker="picker"
  :theme="theme"
  :width-percent="80"
  diagnose-base-url="/ddsat/"
  @close="open = false"
/>
```

普通弹窗：

```vue
<TrendModal
  v-if="open"
  :trend="trend"
  :picker="picker"
  :theme="theme"
  size="1040*720"
  diagnose-base-url="/ddsat/"
  @close="open = false"
/>
```

## 6. 入参

`TrendPanel` 入参：

| Prop | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `trend` | `TrendLoadInput` | 是 | 趋势入参。立刻要画的数据项和时间窗。 |
| `picker` | `PickerInput \| null` | 否 | 待选参数。不传或 `null` 时不渲染待选区域。 |
| `showPicker` | `boolean` | 否 | 是否展示待选区域。默认 `true`。为 `false` 时即使传入 `picker` 也不展示。不展示时 `trend.items` 不能为空。 |
| `theme` | `Theme` | 否 | `'dark'` \| `'light'` \| `'remote-blue'`。 |
| `diagnoseBaseUrl` | `string` | 否 | 诊断分析应用基址，不包含 Hash 路由。未传时为 `/ddsat/`。 |

### 6.1 数据项身份

```ts
interface TrendItemIdentity {
  deviceCode: string
  pointId: string
  kpiId: string
  displayName?: string
  pointName?: string
  unit?: string
}
```

- `kpiId` 必须是采集标识，不要传数字内部编号。
- `displayName`、`pointName` 用于图例和待选列表；缺失时分别回退到采集标识、测点编号。
- 匹配选中项时使用 `deviceCode` + `pointId` + `kpiId`。

### 6.2 趋势入参

```ts
interface TrendLoadInput {
  items: TrendItemIdentity[]
  startTimeMs?: number
  endTimeMs?: number
}
```

- `items` 必填。展示待选区域时可以为空数组；不展示待选区域时不能为空，否则提示「数据项清单不能为空」。
- 最多绘制 10 条，超出只保留前 10 条并提示。
- 未传时间：截止时间为当前时刻，开始时间为当前时刻减 2 小时。
- `items` 为空且待选也未勾选时，图为空，不发趋势请求。

### 6.3 待选参数

```ts
type PickerInput =
  | { type: 'device'; deviceCode: string; deviceName?: string }
  | { type: 'items'; items: TrendItemIdentity[] }
```

| 类型 | 行为 |
| --- | --- |
| 不传 / `null` | 不展示待选区域。`trend.items` 不能为空。只能看趋势入参中的数据项，仍可改时间。 |
| `type: 'device'` | 请求该设备非信号数据项列表，供勾选。按测点编号从小到大分组。可按展示名称聚合；可重置。 |
| `type: 'items'` | 以传入清单为候选，可跨设备。不提供按展示名称聚合。 |

同时传入趋势入参和待选时：

1. 待选区域展示候选。
2. 趋势入参中能匹配到候选的数据项自动勾选，并立刻画图。
3. 匹配不到时仍绘制趋势入参中的数据项；设备列表里对应项不勾选。

只传设备、趋势清单为空时：列表默认不勾选，图为空。

## 7. 典型接入

### 7.1 只看固定几条趋势

不传 `picker`，或传 `show-picker="false"`。用户不能再挑数据项。`trend.items` 不能为空。

```ts
const trend: TrendLoadInput = {
  items: [
    { deviceCode: 'DEV01', pointId: '01', kpiId: 'RMS', displayName: '速度有效值', pointName: '测点01' },
  ],
}
```

```vue
<TrendPanel :trend="trend" :theme="theme" />
```

### 7.2 从一条数据项打开，并允许改选同一设备

这是设备详情「分析」的典型用法。

```ts
const trend: TrendLoadInput = {
  items: [currentItem],
}
const picker: PickerInput = {
  type: 'device',
  deviceCode: currentItem.deviceCode,
  deviceName: deviceName,
}
```

打开后：该条勾选并画图；待选区为该设备非信号列表。

### 7.3 只传设备，进入后由用户勾选

```ts
const trend: TrendLoadInput = { items: [] }
const picker: PickerInput = { type: 'device', deviceCode: 'DEV01' }
```

打开后：已选 0/10，图显示「暂无趋势数据」，直到用户勾选或点击聚合项。

### 7.4 用数据项清单做待选

```ts
const picker: PickerInput = { type: 'items', items: candidateList }
```

候选可跨设备。跨设备勾选时，「诊断分析」会提示须同一设备。

## 8. 主题

`theme` 取值只能是 `dark`、`light`、`remote-blue`。

未传 `theme` 时：若宿主 `html[data-theme]` 已是上述三者之一则跟随，否则为 `remote-blue`。

内容区根节点设置 `data-theme`。样式使用 CSS 变量，不依赖宿主是否引入 ant-design-vue。

## 9. 组件发出的请求

三条接口均经注入的 `request` 发出。路径、请求体和解析规则见 [需求说明 第 8 节](需求说明.md)。

| 时机 | 接口 |
| --- | --- |
| 待选为设备 | 设备下数据项列表，只保留 `signal !== true` 的项 |
| 有勾选或趋势入参命中 | 每条选中数据项各请求一次聚合历史；`aggregateFunc` 固定为 `2`，`reserveDecimal` 固定为 `3` |
| 打开「阈值线」 | 按当前勾选请求启用阈值；关闭开关不丢弃缓存 |

阈值开关默认关闭，关闭时不为画线而请求阈值。

阈值接口的 `severity` 使用 `2`（注意）、`3`（警告）、`4`（危险）。组件仅绘制 `enabled` 为 `1` 且阈值为有效数字的规则。

## 10. 诊断分析跳转

点击「诊断分析」：

- 未勾选：提示「请先勾选数据项」。
- 勾选跨设备：提示须同一设备。
- 单条：新窗口打开 `{diagnoseBaseUrl}?origin=pms&deviceCode={deviceCode}&pointId=&collectKpiId=&st=&et=`。
- 多条：最多 5 个，写入 `sessionStorage.deviceKpi`（含 `startTime` 与 `endTime` 还原时间跨度），新窗口打开 `{diagnoseBaseUrl}?origin=pms&deviceCode={deviceCode}`。超出时提示已取前 5 个。

`diagnoseBaseUrl` 未传时为 `/ddsat/`。宿主若诊断分析不在该路径，传入实际基址（如 `http://<host>/ddsat/`），建议以 `/` 结尾。跳转参数位于 Hash 路由之前，由诊断分析应用从根入口完成内部路由；否则内部路由切换可能丢失 `origin`，导致落地页不自动查询。组件会移除 `diagnoseBaseUrl` 中已有的 Hash 路由。

## 11. 限制

- 同时绘制不超过 10 条趋势。
- 不绘制 `signal === true` 的数据项。
- 待选为设备时，点击展示名称聚合会清空当前选中，改为该名称下的数据项；超过 10 条只取前 10 条。
- 包不保存账号级选中状态，关闭后再次打开按本次入参重新计算。

## 12. 故障排查

| 现象 | 检查 |
| --- | --- |
| 控制台 `data-item-trend: request is not installed` | 入口未 `app.use(TrendAnalysis, { request })`，或 `use` 发生在组件渲染之后。 |
| 有调试条（数据源、token、设备编码） | 那是仓库 playground，不是包导出的内容区。宿主页面不应出现该条。 |
| 待选区不出现 | 未传 `picker`、传入 `null`，或 `showPicker === false`。 |
| 提示「数据项清单不能为空」 | 待选区域未展示且 `trend.items` 为空。不展示待选时必须传入至少一条数据项。 |
| 打开后已选 1 且自动画图 | 趋势入参 `items` 非空，组件按设计勾选并绘制。只要列表、不要预选时传 `items: []`。 |
| 列表有项但对应复选框未勾、图上仍有曲线 | 趋势入参的 `deviceCode` / `pointId` / `kpiId` 与设备列表对不上。`kpiId` 须为采集标识。 |
| 设备列表为空或提示「数据项列表加载失败」 | 检查 `/dosis/...getKpiValueListByBusFilterDoGet` 是否通、token 是否按路径带上。 |
| 图为「暂无趋势数据」 | 当前无勾选，或接口 `code: 200` 且 `data: null` / 空序列。后者按无数据处理，不当失败。 |
| 部分曲线缺失并提示加载失败 | 对应数据项的聚合请求失败，不阻断其他曲线。 |
| 诊断分析打不开或落地页无勾选 | 检查 `diagnoseBaseUrl`、弹窗是否被拦截，以及多条跳转时 `sessionStorage.deviceKpi` 是否同源可读。 |
